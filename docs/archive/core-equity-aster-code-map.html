Modules a connaitre

Backtests / discovery

aster_strategy_registry.py: registry canonique scripts/familles/statuts. A lire avant d'ajouter un nouveau runner.

backtest_strategy_discovery.py: runner principal multi-symboles / multi-timeframes. Produit les CSV V2 tagges.

backtest_aster_v2.py: wrapper v2 unifie, construit un univers plus intelligent via plan/preflight.

backtest_reality_checked.py: relance discovery puis filtre avec le reality check public.

Modele perps

aster_perps_model.py: frais officiels, funding public, cache exchangeInfo, verdict de filtres exchange.

aster_mark_index_replay_filter.py: compare last/mark/index pour eviter les faux edges.

aster_microstructure_replay_validator.py: verifie si les champions auraient ete remplissables via depth + aggTrades.

aster_mcp_market_data_adapter.py: normalise les endpoints publics Aster V3.

Data sources

data_sources/source_validation.py: prouve quels endpoints sont utilisables.

data_sources/public_universe_snapshot.py: construit l'univers public Aster.

data_sources/ws_symbol_quality_report.py: qualite WS par symbole.

Rapports

aster_research_consolidated_report.py: genere le cockpit HTML principal.

research/exchangeinfo_run_status.py: lit les heartbeats des runs exchangeInfo.

research/dual_track_research_report.py: garde exploitation et exploration separees.

Commandes propres a lancer

Suivre les runs exchangeInfo en cours

Set-Location D:\trading-agent\backend
python -m services.onchain.aster.research.exchangeinfo_run_status

Regenerer le cockpit resultats

Set-Location D:\trading-agent\backend
python -m services.onchain.aster.aster_research_consolidated_report

Verifier la microstructure des champions

Set-Location D:\trading-agent\backend
python -m services.onchain.aster.aster_microstructure_replay_validator --champions LABUSDT:5h:long,INTCUSDT:30m:long,CRCLUSDT:2h:long

Ce filtre est read-only: il lit aggTrades/historicalTrades et depth, mesure spread, slippage, gaps, volume reel et nombre de trades, puis retourne microstructure_ok, thin_liquidity, gap_risk ou not_enough_trades.

Suivre les lanes promotion-ready en forward paper

Set-Location D:\trading-agent\backend
python -m services.onchain.aster.aster_promotion_ready_lanes_report --forward-cycle --run-forever --sleep-seconds 300 --forward-window-trades 1000 --persist

Ce runner ne suit que les lanes PROMOTION_READY. Il ne cree aucun trade reel: --persist ecrit seulement dans le ledger paper-trading.

Diagnostiquer la microstructure au moment des entrees

Set-Location D:\trading-agent\backend
python -m services.onchain.aster.aster_promotion_ready_lanes_report --entry-micro-diagnostic --forward-window-trades 1000

Rejoue les lanes PROMOTION_READY, extrait les entrees, puis verifie le flux aggTrades autour du timestamp d'entree. Limite: pas de carnet historique public, donc le test valide la liquidite trade-tape, pas le spread historique exact.

Post-mortem strict du ledger promotion-ready

Set-Location D:\trading-agent\backend
python -m services.onchain.aster.aster_promotion_ready_lanes_report --strict-ledger-postmortem --limit-pairs 60

Lit les sorties paper persistées, rattache chaque sortie a son entree, puis teste si l'entree aurait passe des garde-fous plus stricts: au moins 50 trades, au moins 20k USD de volume quote et aucun gap superieur a 30 secondes dans la fenetre d'entree. Dernier verdict: strict_filter_reduces_damage, donc le filtre reduit la perte mais ne valide pas encore LAB en forward.

Lancer le monitor strict promotion-ready

Set-Location D:\trading-agent\backend
python -m services.onchain.aster.aster_promotion_ready_lanes_report --strict-forward-cycle --run-forever --sleep-seconds 300 --forward-window-trades 1000 --persist

Variante separee du monitor promotion-ready historique. Elle refuse les entrees dont la fenetre trade-tape est trop mince et ecrit dans paper_trading_strict_promotion_ready_forward_monitor.csv avec un event_type distinct.

Relancer le RAG documentaire

Set-Location D:\trading-agent
D:\trading-agent\.venv-rag\Scripts\python.exe D:\trading-agent\rag\scripts\rag_tool.py ingest --domain memory

Garde-fous non negociables

aucun trade reel aucun wallet order aucune API key trading pas de refactor pendant runners actifs read-only public first

Les endpoints signes Aster comme income, leverageBracket, adlQuantile, commissionRate, MMP, strategy orders ou transfers sont connus, documentes, mais bloques tant qu'une policy credentials read-only/testnet n'existe pas.
